# Documentation

`design`は決定済み仕様、`notes`は非規範的な調査記録である。

- README、`scripts/README.md`、Sphinx文書は現在形の常体で記述する。
- 一段落では一つの論点を扱い、原則として2〜4文に収める。
- designは対象と責務、主要な境界または流れ、保証と検証の粒度で記述する。
- 手順は動作から始め、要件は主語、保証内容、所有境界を一文で示す。
- 一般名詞は日本語、コード識別子、外部API名、安定IDは英語で表記する。
- 日本語とinline codeの間に不要な半角空白を置かない。
- 同じ仕様を複数の章で定義しない。
- 時点や編集経緯をdesign本文へ含めない。
- 実装で保証できる構造はテストへ置き、判断原則だけを文書へ置く。
- デフォルト、環境変数、CLI surface、OpenAPI、品質成果物は所有するソースコードを正本とする。
- 実測件数、最新結果、生成画像をソース文書へ固定しない。
- 調査結果が仕様になった場合はdesignへ移し、役目を終えたnotesとassetを削除する。
